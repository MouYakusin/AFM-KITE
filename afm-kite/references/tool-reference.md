# Generic Tool Reference

This reference describes the generic tool surface expected by this skill. Tool implementations may be Python callables, MCP tools, CLI wrappers, or other compatible adapters. The public contract should remain generic.

This file is the canonical fallback tool-result contract when the active runtime does not provide an equivalent execution contract.

## Naming

Section headings use the exact snake_case callable names registered by this repository. Tool results use a separate kebab-case `step` identifier. For example, call `matrix_level`; expect `"step": "matrix-level"` in its result.

## Shared Conventions

Public tools always return:

- `status`: exactly `"ok"` or `"error"`; a missing or unrecognised status is a protocol error.
- `step`: generic stage name.
- `message`: required for errors and optional for success.
- `artifacts`: paths to generated matrices, tables, images, masks, manifests, or reports.
- `summary`: compact numeric or structural summary when useful.
- `result`: complete domain values on success.

Some errors also return `error_code`, `recoverable`, and `details`.

Each callable writes beneath its explicit `output_dir` and returns the generated paths in `artifacts`. The active runtime and task prompt own the legal persistent and temporary roots; this reference does not redefine their routing policy.

## Data and Matrix Tools

### `data_ingest`

Parse one physical raw export into reusable matrix artifacts and one data manifest.

Within this Skill, `data_ingest` is the mandatory boundary for every dedicated-tool workflow that begins with user-supplied AFM/KPFM data when the callable is available. When it is unavailable but `generic_compute` is available, use the capability-aware fallback in `SKILL.md` instead of attempting this callable or reporting it as missing. Its public signature is:

```python
data_ingest(input_path, output_dir="outputs/data/ingest")
```

Each call accepts exactly one physical file. The file may be single-channel or multichannel; all detected channels are split, structured, and saved regardless of which channels a later analysis will use. If the requested analysis covers N files, invoke `data_ingest` N times. Then pass the returned matrices, metadata, and `afm.data-manifest/v1` paths downstream. Do not re-ingest artifacts generated by the current workflow. A user-supplied `.npy` is not a supported workflow entry point; `.npy` files created by deterministic stages remain valid internal artifacts.

Generic roles:

- `reference_channel`: channel used for geometry, topography, or segmentation.
- `target_channel`: channel used for comparison or primary measured signal.
- `quality_channel`: channel used to assess artifacts or measurement quality.
- data-group members: separately ingested files assigned stable member IDs and semantic labels.

### `data_group_build`

Organize two or more single-file ingest manifests without reading the raw files again. Its public signature is:

```python
data_group_build(
    data_manifest_paths=[manifest_a, manifest_b],
    output_dir="outputs/data/data_group",
    relationship="collection",
    labels=None,
    reference_data_index=0,
    registration="none",  # or "translation"
    registration_channel="height",
    relationship_source="agent_default",
)
```

Supported relationships are `collection`, `ordered_conditions`, `replicates`, and `time_series`. `data_group_build` does not infer a relationship. The Agent chooses it using explicit user semantics first, workflow-required semantics second, and `collection` as the safe default. Set `relationship_source` to `user_explicit`, `workflow_required`, or `agent_default` accordingly. Never use filenames alone as relationship evidence.

The result is an `afm.data-group/v1` manifest containing stable member IDs, labels, original and active channel indexes, channel compatibility, warnings, and optional translation-registration transforms. Channel matching uses normalized channel names; partial or ambiguous matches are preserved and reported rather than silently discarded.

Translation registration uses linear interpolation and fills coordinates outside the moving matrix with `NaN`; it never duplicates the nearest edge value.

Avoid public arguments named after a scan mode. Use generic roles and contracts.

### `matrix_inspect`

Inspect shape, finite range, unit, metadata, and missing-value coverage without generating heavy artifacts.

### `matrix_level`

Remove a selected low-order trend from an existing matrix without inferring the matrix's physical role.

```python
matrix_level(
    matrix_data_path,
    trend_mode,  # "plane", "line", "none", or "auto"
    output_dir="outputs/data/level",
    metadata_path="",
)
```

`trend_mode` is required. Domain workflows in `registry.md` choose its value; the public tool does not choose a mode from sample identity.

### `matrix_filter`

Apply a generic image filter such as Gaussian, median, mean, Sobel, or Laplace to an existing matrix.

### `pseudocolor_render`

Render a numeric matrix to an image for qualitative review. Every rendered matrix includes a colorbar and a scale bar. For height-derived raw, leveled, filtered, residual, or other processed matrices, the renderer first uses an explicit `metadata_path`, then auto-discovers a same-stem `_metadata.json` sidecar. These units control the axes, scale bar, and colorbar. If physical metadata is genuinely unavailable, value and lateral units default to `μm`, the lateral calibration defaults to `1 μm/pixel`, and the result marks the decoration as defaulted. The image must not be used as the source of quantitative values.

Use `plot_title` to distinguish the physical role of otherwise height-like matrices. `color_scale_mode="auto"` uses percentile-clipped limits; `color_scale_mode="symmetric_zero"` expands those limits symmetrically about zero for residual or contrast maps. Title styling and channel-title normalization are applied deterministically by the renderer.

Set `color_min` and `color_max` together to apply explicit shared display limits to two or more already-existing comparable matrices. Explicit limits require `color_scale_mode="auto"` and do not alter any numeric artifact. Prefer limits derived from the existing ingest or matrix-inspection summaries; do not run another analysis stage solely to choose display limits.

### `matrices_subtract`

Subtract one aligned matrix from another and write a residual or contrast matrix.

## Region and Feature Tools

### `value_regions_segment`

Segment regions based on matrix values. Parameters may include polarity, minimum area, expected count, matching `metadata_path`, and `write_plots`. Use `dark` for low-height targets, `bright` for high-height targets, and `auto` only when target-height semantics are unresolved. Positive label values identify selected regions and do not imply bright polarity. Set `write_plots=true` only when the active workflow requests the categorical mask and height-based region overlay; set it to `false` when no segmentation review render is requested. The numeric label matrix and regions JSON are always written. The result includes `quality.passed` and stable `quality.flags`; a successful computation with `quality.passed=false` is not a scientifically valid segmentation and must not feed a region-dependent measurement. Auto mode selects the highest-scoring quality-passed candidate when one exists and otherwise preserves the best diagnostic candidate with failed quality. Explicit `bright` or `dark` requests are never silently changed to the opposite polarity. When enabled, the height-based region overlay includes a colorbar and scale bar; matching metadata is auto-discovered from a same-stem sidecar when the explicit path is omitted, with the suite's recorded `μm` default used only when metadata is absent.

### `gradient_regions_segment`

Segment regions based on gradient magnitude or edge-like structure. This is useful when the workflow text asks for boundary-like regions, but the tool remains generic.

### `local_outliers_detect`

Detect local outlier components in a whole matrix, background area, or segmented regions. Pass matching metadata so its height-based overlay has physical axes, a physical scale bar, and a unit-bearing height colorbar. Workflow text may later interpret these as contamination or defects, but the tool should report them generically as local outliers.

### `feature_select`

Select one target from an existing value-region result by filtering, sorting, and applying a one-based rank. Supported metrics are `area_px`, `mean_value`, `median_value`, `median_prominence`, and `absolute_prominence`; supported sort orders are `ascending` and `descending`; supported polarity filters are `any`, `raised`, and `depressed`.

Examples:

- second-largest area: `selection_metric="area_px"`, `sort_order="descending"`, `rank=2`;
- highest raised feature: `selection_metric="median_prominence"`, `sort_order="descending"`, `polarity="raised"`;
- deepest depressed feature: `selection_metric="median_prominence"`, `sort_order="ascending"`, `polarity="depressed"`.

Ranking occurs after the area, edge-margin, and polarity filters. The result contains the complete candidate ranking and rejection reasons in addition to an `afm.selected-feature/v1` JSON and selected-feature mask.

Prominence is calculated against a local label-zero ring by default. Configure the ring with `local_ring_inner_px` and `local_ring_outer_px`; the inner gap keeps transition pixels away from the reference and the outer radius limits the reference to the feature neighborhood. `min_local_background_samples` controls the minimum finite label-zero support. When that support is unavailable, the tool falls back to the global label-zero background and records `background_reference_used="global_background_fallback"` plus a reason in the candidate and selected-feature diagnostics. Set `prominence_reference="global_background"` only when a shared whole-image reference is explicitly required.

`render_candidates_overlay=true` optionally renders the matrix already supplied to `feature_select` with every segmented candidate outlined and labeled `F###`. `render_selected_overlay=true` keeps all candidate outlines as gray context while emphasizing only the selected feature with a cyan outline and label. The two flags may be enabled independently on the same selection call; they never rerun segmentation, ranking, or measurement.

### `feature_line_build`

Build one reusable `afm.feature-line/v1` contract from a selected-feature JSON. The default `minor_axis` direction seeks a short crossing through an elongated feature; `major_axis`, X, Y, and explicit-angle directions are also available. The tool must verify that both endpoints and both substrate windows lie on label zero, the line crosses the selected label, and it does not cross another segmented feature. The contract records one stable `line_id`, start/end points, sample coordinates, and left-substrate/feature/right-substrate windows.

### `residual_features_prepare`

Create a contract that links original, leveled, and residual artifacts for residual-feature analysis.

### `residual_features_segment`

Segment candidate components in a residual matrix.

### `residual_features_measure`

Measure residual-feature contrast against local reference regions. `selection_mode="all"` measures every candidate. `selection_mode="largest_area"` first selects the greatest `area_px`, breaking ties by the smaller label value, and then measures only that component. `render_candidates_overlay=true` writes an all-candidate review image whose outlines and `C###` labels are gray. `render_selected_overlay=true` writes a selection image that retains gray candidate outlines but hides every unselected label; only the selected candidate has a cyan outline and `C###` label. Both flags default to false and may be selected independently. `render_overlay=true` remains a compatibility shortcut that writes both images. Rendering does not cause unselected candidates to be measured.

## Measurement Tools

### `paired_region_catalog`

Build the condition-A-frame target-channel difference before selecting a region. The tool consumes an ordered two-member `afm.data-group/v1` and one Height-derived `afm.value-regions/v1` artifact. It inverse-samples the original condition-B target matrix using the Height translation, writes the registered condition-B field and full-field B-minus-A matrix, and records paired condition-A, condition-B, and change statistics for every `F###` region.

The output is `afm.paired-region-catalog/v1` with JSON and TSV catalogs, a full-field valid mask, registration provenance, per-region coverage and quality gates, and optional `paired_change_atlas_png_path`. Set `render_change_atlas=true` to render the already-calculated full-field difference with Height-derived boundaries, stable `F###` labels, and each region's mean change. Rendering does not trigger another numeric stage.

### `paired_region_select`

Select one region from `afm.paired-region-catalog/v1`. Supply exactly one of:

- `feature_id`, such as `F003`;
- both `x_px` and `y_px` for point-based selection; or
- neither, to rank eligible regions by `selection_metric`, `sort_order`, and one-based `rank`.

Ranked metrics are `area_px`, `condition_a_mean`, `condition_b_mean`, `change_mean`, `absolute_change`, and `paired_finite_coverage`. `min_area_px` and `min_coverage` filter ranked candidates. The result uses `afm.selected-feature/v1`, preserves the full Height-defined feature mask, and can therefore be passed directly to `paired_region_measure`. Set `render_selected_overlay=true` to highlight the selected mask on the existing full-field difference without recomputing the catalog.

### `paired_region_measure`

Measure one selected reference-frame region across exactly two ordered conditions. The tool reads a Height-derived translation from `afm.data-group/v1`, samples the original condition-B target matrix at inverse-mapped coordinates, and measures both conditions over the same finite paired pixels.

```python
paired_region_measure(
    data_group_json_path,
    selected_feature_json_path,
    target_channel="DCbias",
    mask_mode="eroded",  # or "full"
    erosion_px=2,
    interpolation="linear",
    min_coverage=0.95,
    min_region_pixels=20,
    max_shift_fraction=0.1,
    calculate_background_normalized=False,
    background_ring_inner_px=3,
    background_ring_outer_px=15,
    write_difference_matrix=False,
    output_dir="outputs/data/paired_region",
)
```

Requirements and behavior:

- The data group must use `relationship="ordered_conditions"`, contain exactly two members, and use condition A as `reference_data_index=0`.
- Translation must come from the group's reference channel, normally a height-like channel. The tool never registers from the measured target contrast.
- The selected-feature mask must use the condition-A reference frame.
- For a registered pair, condition B is sampled from `original_channel_index`, using `condition_b_source_yx = condition_a_reference_yx - shift_yx_px`.
- Out-of-bounds and non-finite samples are omitted; edge values are never copied.
- Before, after, and B-minus-A statistics use exactly the same valid paired pixels. `mean(B-A)` therefore equals `mean(B)-mean(A)` apart from floating precision.
- `mask_mode="eroded"` removes the requested number of boundary pixels. If the eroded mask contains fewer than `min_region_pixels`, the full mask is used and the fallback is recorded.
- Set `calculate_background_normalized=true` only when the user requests the optional local-background drift check. It uses a label-zero ring around the full selected feature and reports `region_change_B_minus_A - background_change_B_minus_A` as a supplementary result.

The output is `afm.paired-region-measurement/v1`. It contains member order, transform provenance, coverage diagnostics, region statistics, optional local background statistics, warnings, and a `quality.passed` gate. The selected analysis mask and actual finite paired mask are always written. When `write_difference_matrix=true`, the tool also writes a region-only B-minus-A matrix with `NaN` outside the valid paired mask plus matching target-channel metadata; pass that matrix to `pseudocolor_render` with `color_scale_mode="symmetric_zero"` and `colormap="coolwarm"` only when the render is requested. This is a display-only choice over the already calculated paired differences.

### `matrix_roughness_statistics`

Calculate deviation and distribution statistics from an existing matrix. It does not remove trends or filter internally.

```python
matrix_roughness_statistics(
    matrix_data_path,
    statistics_scopes,  # any of "matrix", "regions", "region_union", "background"
    regions_data_path="",
    output_dir="outputs/data/roughness",
    value_unit="",
    metadata_path="",
    outliers_data_path="",
)
```

- `statistics_scopes` is required and may contain `matrix`, `regions`, `region_union`, and `background`.
- `matrix` evaluates all finite values.
- `regions` measures each positive label in the supplied label matrix independently.
- `region_union` measures all finite values whose supplied segmentation label is greater than zero as one combined mask. Its Sa and Sq are calculated around the pooled union mean, not averaged from per-region Sa or Sq values.
- `background` measures label zero.
- `regions`, `region_union`, and `background` require `regions_data_path`.
- `regions`, `region_union`, and `background` require a segmentation with `quality.passed=true`; legacy region artifacts are re-evaluated from `selected_score` and `score_diagnostics`, while failed or unverifiable segmentation returns an error before measurement.
- `outliers_data_path` is valid only with `regions`, `region_union`, or `background`.
- With `regions`, every returned record retains `region_id`, `label_value`, `area_px`, optional `area_physical`, `mean_height`, `Sa`, `Sq`, units, and supporting statistics.
- With `region_union`, the returned `region_union` record retains the contributing `label_values`, `region_count`, combined area, mean height, Sa, Sq, units, and supporting statistics.
- The tool calculates every positive-label region once and does not choose which region records belong in the final report. A workflow may rank the returned records deterministically by a returned field without invoking the tool again.
- Domain interpretation of the returned deviations belongs in the Skill.

### `frequency_direction_candidates`

Return direction candidates derived from a two-dimensional frequency representation, together with numerical quality diagnostics.

```python
frequency_direction_candidates(
    matrix_data_path,
    minimum_period_samples,
    maximum_period_samples,
    output_dir="outputs/data/periodic_orientation",
    metadata_path="",
)
```

The period-search bounds are required. This generic contract does not designate one candidate as the domain-specific measurement direction.

### `directional_series_extract`

Reduce a matrix to a one-dimensional series along a supplied direction.

```python
directional_series_extract(
    matrix_data_path,
    direction_mode,  # "x", "y", or "angle"
    direction_degrees,
    bin_size_samples,
    smoothing_sigma_samples,
    output_dir="outputs/data/profiles",
    metadata_path="",
)
```

All reduction choices are explicit. Domain workflows decide which direction and parameter values to use.

### `periodic_series_statistics`

Calculate periodic, segment, and level statistics from an existing numeric series without assigning a physical interpretation to those statistics.

```python
periodic_series_statistics(
    series_data_path,
    upper_percentile,
    lower_percentile,
    minimum_period_samples,
    maximum_period_samples,
    sample_spacing,
    coordinate_unit,
    value_unit,
    output_dir="outputs/data/periodic_profile",
    coordinate_column="",
    value_column="",
)
```

Thresholds, period bounds, calibration, and units are required. The Skill maps the returned statistics to requested scientific quantities.

### `line_profile_sample`

Sample exactly one numeric matrix along an existing feature-line contract. Call the tool separately for every required member and channel. Pass a matching metadata path when available so distance and value units are preserved. The matrix shape must match the line-contract shape. `line_width_px=1` preserves a center-line profile. A larger width samples symmetric perpendicular offsets and aggregates each position with `aggregation="median"` (default) or `"mean"`. Out-of-bounds band samples are omitted rather than edge-padded. The result records the offsets, finite sample count, and band standard deviation at each position, and saves both the aggregated profile NPY and the complete band NPY alongside the `afm.line-profile/v1` JSON and TSV artifacts.

### `line_profile_measure`

Measure one or more sampled profiles that share the same `line_id`, coordinates, windows, interpolation, band width, and aggregation rule. For each profile, calculate left, right, combined-substrate, and feature statistics; signed and absolute feature-minus-substrate contrast; robust extreme contrast; feature-window width; and substrate asymmetry. With exactly two ordered profiles, also calculate the second-minus-first contrast change. Keep the numeric result generic: only workflow interpretation may call a signed height-channel contrast height or depth.

### `line_profile_render`

Optionally render a numeric profile plot, a line-position overlay, or both from existing line/profile/measurement artifacts. An overlay requires an explicit matrix path. When that matrix is height-derived, its same-stem metadata sidecar is discovered automatically; an explicit `overlay_metadata_path` takes precedence, and `overlay_value_label="Height"` keeps the semantic label clear. Without matching physical metadata, value and lateral units default to `μm` with a recorded `1 μm/pixel` lateral assumption. Band profiles include a one-standard-deviation ribbon in the numeric plot and band-edge guides in the position overlay. This tool performs no measurement, and its PNG outputs must never be used as quantitative inputs.

## Error Payload Contract

An error result must set `status="error"` and provide a diagnostic `message`. When `recoverable=true`, `details` must contain enough structured information for the caller to correct the request. These fields describe the error; retry, dependency, and final-report behavior belong to the active runtime contract.

Artifact-policy and workspace-path violations use `error_code: "artifact_policy_violation"`, set `recoverable: true`, and list legal virtual roots in `details.allowed_roots`. Adapters must convert these predictable validation failures into the result contract instead of raising raw exceptions to the Agent.

If a deterministic operation reports `"status": "error"` without a diagnostic message, the public result boundary must add one before exposing the payload.
